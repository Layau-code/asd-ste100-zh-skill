# 中文受控写作判读参考

这些规则借鉴 ASD-STE100 的消歧目标，针对中文常见句法与标点重新设计。它们是写作约束，不是正式中文标准的认证条款。

| 检查点 | 容易误读的原文 | 可在原意明确时采用的写法 | 注意 |
|---|---|---|---|
| 动作主体 | “用户提交订单后，系统审核并通知他。” | “用户提交订单后，系统审核订单。系统通知用户。” | 只有原文已说明执行者时才补出主语。 |
| 条件归属 | “如果导入失败或文件为空，删除它并重试。” | 暂不改写，先确认两个条件是否都对应“删除并重试”。 | 不要擅自决定条件与动作的对应关系。 |
| 指代 | “读取配置和缓存，若其失效则重新生成。” | 暂不改写，先确认“其”指配置还是缓存。 | 只在指代已确定时重复具体名称。 |
| 否定范围 | “不支持管理员和访客修改。” | 暂不改写，先确认是两类用户都不能修改，还是仅禁止同时修改。 | 不要自行选择一种逻辑范围。 |
| 并列关系 | “A 和/或 B” | “满足 A、B 中至少一项，也可以同时满足两项。” | 只有原文确实使用通常的兼容或含义时才能这样展开。 |
| 时间与状态 | “任务完成后可下载结果。” | “任务完成后，可以下载结果。” | 原文没有说明谁下载、何种状态即为完成，不要擅自补充。 |
| 概率和承诺 | “请求可能失败。” | “请求可能失败。” | 不能改成“请求会失败”或“请求失败”。 |
| 程度词 | “尽快处理异常。” | “尽快处理异常。” | 若期限重要但未知，应指出需要明确期限，不能删除紧迫性或编造时限。 |
| 术语切换 | “移除成员；下一步删除用户。” | 保留原词，先核实两个动作是否相同。 | 不要为了统一术语改变操作对象或后果。 |
| 连续动作 | “先校验文件并上传，然后检查结果并通知用户。” | “1. 校验文件。2. 上传文件。3. 检查结果。4. 通知用户。” | 原文没有说检查哪项结果，不要自行指定。 |

## 特别容易丢失的信息

- `可能`、`大概`、`通常`、`仅`、`最多`、`至少`、`除非`和`建议`属于事实或约束的一部分。
- `应`与`必须`、`可`与`会`、`不应`与`不得`并不等价。
- 中文没有英文那样的词界；不能把 STE 的“20 个单词”机械换成某个汉字数。
- `被`字句不必一律改成主动句。如果执行者未知、无关或不能从原文确定，保留原句更准确。
- 分号在中文里可以清楚地分隔并列分句。只有分号掩盖步骤、条件或主语时才拆句。
- `及`、`或`、`和/或`不能一律互换。先识别“全部满足”“满足任一项”还是“列举对象”。

## 无法确定原意时的交付方式

给出最小范围的歧义说明，例如：“‘不支持管理员和访客修改’可能表示两类用户都不能修改，也可能只禁止双方同时修改。请确认适用范围。”不要选一个版本冒充原意。

## 与英文技能的功能对应

| 英文技能关注点 | 中文应检查的问题 | 自动检查的边界 |
|---|---|---|
| 一词一义、术语一致 | 同一对象是否被称为“用户”“客户”“申请人”；同一动作是否轮换“检查”“核查” | 仅能提示候选词，无法证明指同一概念。 |
| 主动语态 | 省略的执行者是否让责任不清；“被”字句是否需要说明执行者 | 不能凭“被”字判错。 |
| 一个步骤一个动作 | “先……并……然后……”中是否包含可分开的动作 | 脚本只能提示连词，必须人工识别动作边界。 |
| 句长和段落长度 | 是否混入多个条件、动作或话题 | 汉字数量只是复核线索，不是合规阈值。 |
| 不省略必要句子成分 | “审核后发送”中的执行者、对象、条件是否可还原 | 缺失信息不能自行补全。 |
| 保留情态与时态 | `可能`、`通常`、`已`、`正在`、`将`、`必须`、`建议`是否保持原强度 | 不把情态词本身当作坏词。 |
| 动词而非动作名词 | “进行检查”“实施删除操作”是否隐藏直接动作 | 固定术语与法规名称应保留。 |
| 不用含糊的搭配 | “拉通”“打通”“赋能”是否有明确对象与操作 | 普通介绍文字可能容许此类词。 |
| 分号、列表和并列 | `；`是否连接独立步骤；列表项是否以“和”“或”残留 | 中文分号可能正确，需按语义判断。 |
| 领域术语表 | 首次出现的缩写或业务词是否需要定义 | 不擅自更改产品、接口或字段名称。 |

## 审查顺序

先核对事实与承诺，再检查条件和否定范围，然后处理指代与术语，最后才压缩句子。不要先为了简短删除 `可能`、`至少`、`除非` 等限定，再尝试从上下文补回来。

若一句话可以有两种会导致不同操作的解释，应把两种读法写给作者确认。若问题只影响风格，可选择更清楚的表达，并保持原有信息量。
